# 运行生命周期与会话关联

第五阶段为启动器增加非阻塞运行句柄，并接入托管 Codex 的生命周期事件。Provider、Run 和 Session 是不同身份：一个账号可以启动多个进程，一个进程可以打开多个会话，同一个会话也可以被多次恢复。Home 和项目目录相同不能作为归属证据。

## 启动与退出

`Launcher::start` / `Provider::start` 返回 `RunningAgent`，提供 `pid`、启动记录快照、`try_wait`、`wait` 和 `terminate`。内置本地 Agent 和托管 Codex 都支持该能力。自定义启动器可以保留原有前台接口，通过 `supports_start` 明确声明能力；不支持时返回 Unsupported。

`start` 完成原有同步、认证、配置和能力检测后创建进程，不等待进程退出；这些准备操作仍应在 UI 的后台任务中调用。`spawn`、CLI 和当前终端恢复保持原有等待行为。子进程继承原有终端输入输出，非阻塞句柄不是脱离终端的后台服务。

托管启动先在同一事务保存 Run、配置快照和 `process_started` 事件。记录失败时终止并回收子进程。句柄完成等待后，在同一事务保存退出状态和 `process_exited`，重复 `wait` / `try_wait` 不重复写退出事件。OAuth 共享租约由句柄持有直至退出完成处理，原有子进程继承的租约保护仍然生效。

丢弃仍在运行的句柄会把等待和退出记录交给后台线程，不阻塞调用者，也不主动终止 Agent。若 Usage 整个进程提前退出，后台线程无法保证写入结束记录；读取状态时仍按 PID 与进程启动指纹核对，不能把“没有结束记录”直接显示成运行中。`terminate` 只操作句柄拥有的 Child，随后仍需等待回收。

## Codex 事件与信任

支持生命周期 hooks 的 CLI 会在本次启动参数中注入五类回调：`SessionStart`、`UserPromptSubmit`、`Stop`、`Interrupt` 和 `SessionEnd`。此功能独立于 Bark 开关，不发送推送或网络请求。当前以 CLI 帮助中存在 hook 信任选项作为能力边界；旧版 CLI 仍可启动和记录进程，未取得会话事件时不猜测绑定。

回调命令固定为当前 Usage 可执行文件的 `codex event`。每次运行的根目录、Home 和运行 ID 通过子进程环境传递，不进入 hook 命令字符串，避免每次启动产生不同的信任定义。保留账号原有的同类 hooks，追加 Usage 处理器；项目与插件 hooks 仍由 Codex 加载。用户显式关闭 hooks 或在启动参数覆盖它们时，不强制恢复，也不添加 `--dangerously-bypass-hook-trust`。

**首次启动或 Usage 回调定义变化后，需要在 Codex 的 `/hooks` 中检查并信任 Usage hooks。** 尚未信任、功能被关闭、CLI 不支持或没有持久元数据时，进程记录仍存在，`sessions` 保持为空。运行中的旧实例不会自动注入新回调，应重新启动或恢复会话。

官方事件与信任规则见 [OpenAI Hooks](https://learn.chatgpt.com/docs/hooks)。`Stop` 是轮次停止事件，其他 Stop hooks 仍可能要求继续；`SessionEnd` 是主线程关闭事件，不能当作进程已退出。中断和进程异常退出也分开表达，不依据缺失的回调推断执行成功。

## 关联验证与存储

回调核对运行 ID、运行对应的托管 Home、PID 与启动指纹，以及该 Home 中会话元数据的用户线程来源。复用现有只读元数据核验器，排除标题任务、子代理和无法确认的临时线程；不依据名称、时间接近或目录相同补写关系。启动记录尚未提交时允许短暂等待；运行已结束或身份不匹配时拒绝写入。

`run_sessions` 按 `(run_id, session_id)` 保存经过事件确认的关系、实际事件 cwd、最新活动状态、轮次和模型。数据库事务同时追加 `run_events`。输入最多读取 1 MiB，只提取白名单字段；提示词、助手正文、工具参数和原始 payload 不进入事件库或事件日志。每次回调的日志操作都关联原 Run，并记录接收、核验来源、拒绝原因及写入结果。

压缩后的 `SessionStart` 不会把正在执行的轮次重置为空闲；迟到的 Stop / Interrupt 不覆盖另一轮的状态。来自回调的模型保存在会话状态中，不替换启动侧 `RunContext`，也不构成端点或凭据证明。恢复会话现在可以通过事件关联到新 Run，但其 API 资源身份仍保留原有未解析边界，详见[资源关联](run-resource-binding.md)。

旧记录没有事件或会话关系，读取时返回空列表；只读首页不会迁移数据库或补写历史。正常打开管理器时创建新增表，不改写原有 Run 和资源证明。

## 查看与首页

```sh
usage codex runs --json
usage codex run-events <运行UUID> --json
usage codex run-events <运行UUID> --limit 50
```

`runs --json` 的 `sessions` 表示确认过的会话集合。`run-events` 按事件序号返回最近指定条数，默认 100、最多 1000；进程退出状态仍在对应 Run 上。事件来自本机回调，不宣称是服务端计费记录或完整 Agent 审计流。

首页项目标题只显示目录名和收录会话数量，例如 `usage (12)`，下方保留完整路径。首页不展示没有加载的 Token 统计；F3 完整会话页仅在接入用量记录后显示累计值。

会话旁显示已经核验的运行状态：执行中、等待输入、已中断、会话已关闭、进程已退出等。同一会话被多个存活实例打开时显示实例数量；不在界面展示内部 Run / Session ID。原有 Enter 恢复仍使用该会话自身的账号、Home 和 Agent。

首页可见时每两秒在后台只读更新运行状态，读取范围限于最近 1000 条运行、未记录结束的运行优先；不重新查询 Provider 模型、余额或厂商状态，也不重新扫描会话目录。状态未变化时不触发额外重绘。`refresh_seconds=0` 关闭定时轮询，首次加载和手动刷新仍可更新。读取失败清除旧活动标记并显示警告，选择与滚动位置保留。

## 验证

测试以合成凭据和本机模拟 Agent 验证并发启动、不同会话的独立归属、恢复到新 Run、内部线程过滤、迟到事件、重复等待、终止、后台回收、OAuth 租约、旧库只读以及 UI 状态代次。CLI 回归实际运行注入的回调子进程，不依赖 Bark。

另使用本机 Codex CLI 0.163.0 的 `features list` 做离线配置验证，确认五类运行 hooks 与 Bark 审批 hook 能同时加载；未绕过 hook 信任，未发起推理或推送。此验证发现并修复 JSON 高精度数字转 TOML 时将 timeout 序列化成对象的问题，运行与 Bark hooks 现共用直接序列化整数的构造器。

2026-10-17 全量 302 项测试串行通过（250 项库测试、52 项集成测试），格式检查、Clippy（全部 target，警告视为错误）及差异检查通过。

## 未托管 Home 的通知恢复

首页和 F3 恢复默认 Home 或其他本地 Codex 会话时，也通过本次启动参数注入 Bark；当前终端使用本地启动器，Ghostty 和复制命令通过隐藏的 `codex resume-local` 命令进入同一启动器。保留原 Home 和认证环境，不创建托管账号、运行记录或生命周期绑定，不修改原配置与认证文件。清除父进程的托管运行上下文，避免错误继承归属。通知关闭时清除继承的 Bark 标记，不添加回调。

回归测试覆盖这三种恢复入口、回调实际到达 Usage、原 notify 每次调用一次、独立启动上下文、关闭开关、原文件保持不变和退出码传递。启动事件 `bark_local_launch` 进入 `bark logs`，区分未注入、未收到回调和屏幕条件过滤。已有进程无法补注入，修复后应重新从 Usage 恢复会话。
