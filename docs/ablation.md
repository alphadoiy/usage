# 代码消融实验（2026-09-29）

## 范围与方法

在本机使用固定的三张合成卡片和 88×18 的内存终端缓冲区。每种 TUI 样式重复绘制 3,000 次，对比现有完整路径与预先构建好 `CardView` 后只绘制卡片的路径。使用 `cargo test --release --offline`，以下绘制数据取预热后的第二次运行。实验不包含真实终端 I/O、网络请求和凭据读取。

一次性查询实验给三个合成 provider 各设置 200 ms 的固定延迟，比较当前串行调用与并行等待。功能消融在隔离副本中关闭独立的 `usage statusline` 命令及其模块，用相同的 release 构建配置比较可执行文件大小；原仓库没有删除该功能。基线的 27 个测试全部通过。

## 结果

| 消融项 | 当前实现 | 对照实现 | 观察 |
| --- | ---: | ---: | --- |
| Braille 卡片，单帧 | 11.0 µs | 9.2 µs（预建视图） | 少约 1.8 µs |
| 圆点卡片，单帧 | 10.1 µs | 9.2 µs（预建视图） | 少约 0.9 µs |
| 圆环卡片，单帧 | 37.0 µs | 35.1 µs（预建视图） | 少约 1.9 µs |
| 样式注册表构建 | 0.30 µs/次 | — | 热路径开销很小 |
| 三个 provider 的一次性查询 | 606 ms（串行） | 202 ms（并行） | 合成延迟下降约 2/3 |
| release 可执行文件 | 6,387,504 B | 6,138,112 B（去掉独立状态栏命令） | 少 249,392 B，约 3.9% |

隔离副本关闭状态栏命令后，剩余的核心测试通过。该消融同时删除了状态栏命令的测试，不能用它证明该命令的行为仍然存在。

## 实施状态

- `--once` 与 `--json` 已改为同时启动所有 provider 查询，并按配置顺序输出；单个查询任务崩溃时返回该 provider 的临时错误快照。
- `CardView` 现在直接接管已生成的圆环与进度条列表，省去构建时的第二次复制。
- 合并了重复的退出码分支，清理了 Clippy 指出的等价写法。第二轮结束时 34 个测试通过，`cargo clippy --offline --all-targets -- -D warnings` 通过。
- 第二轮将 TUI 改为按查询结果、按键、窗口尺寸变化和倒计时秒数重画。空闲状态下按原先 80 ms 轮询估算，每分钟最多约 60 次重画，原先约 750 次；输入轮询仍保持 80 ms，以维持查询结果的显示延迟。这个次数来自调度逻辑，并非终端 I/O 的实测值。
- Claude、Codex、Grok 的本地凭据读取移入阻塞线程；Keychain 子进程最多等待 10 秒。TUI、`--once` 和 `--json` 的单个 provider 查询最多等待 20 秒，独立状态栏的单个 provider 查询最多等待 4 秒。超时返回临时错误，TUI 会沿用上一次成功结果。
- 没有删除独立状态栏命令，也没有增加视图缓存。

## 判断

1. **一次性查询的并发最值得先做，现已完成。** 实验基线中的 [`print_once()`](../src/cli.rs) 逐个等待 provider；TUI 和独立状态栏命令已经并发查询。现在一次性查询也按配置顺序收集并发结果。合成数据说明潜在收益，不能代表真实接口延迟。
2. **视图缓存和注册表缓存暂不值得单独重构。** [`render_cards()`](../src/ui/app.rs) 每次重画会重建注册表和视图，但预建视图仅减少约 1–2 µs/帧。第二轮已让空闲界面按秒重画并在状态变化时立即重画。真实终端输出、CPU 与电量消耗仍未测量。
3. **独立的 `usage statusline` 命令是可选功能，不是 TUI 三种画法的依赖。** 它承担宿主 JSON 解析、Git 分支、缓存和独立输出，约占 [`src/statusline.rs`](../src/statusline.rs) 的 564 行。若产品只需要 TUI，删除它能减小维护面和约 3.9% 的 release 二进制体积；若有人将其嵌入 agent 底栏，则应保留。`statusline` 画法本身仍适用于所有 provider。
4. **工厂和注册表应保留。** [`ProviderFactory`](../src/providers/mod.rs) 的包装很薄，但这正是当前扩展约定；三个 provider 的线性查找与样式注册表构建都不是瓶颈。把它们换成硬编码分支会牺牲扩展能力，性能收益缺乏证据。
5. **小范围冗余已清理。** 实验基线中 [`CardView`](../src/view.rs) 构建时先生成 `Vec` 再通过切片复制一次；`print_once()` 的两个成功分支完全相同。原先 Clippy 报出的 14 个 lint 已清除，查询协议保持不变。

## 限制

- 绘制计时是单机合成数据；首轮运行的 Braille 数据明显偏高，故使用预热后复测值。它不包含 `Terminal::draw` 的真实写终端成本。
- 二进制大小取 macOS release 可执行文件，未使用 `strip`；不同平台或链接参数会改变绝对值。
- 未对真实登录态、官方接口延迟、网络失败及终端字体进行测量。
