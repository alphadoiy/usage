# 首页：Provider、厂商状态与项目会话

`usage` 的 F1 首页默认展示三个看板。宽屏上方为 Provider 与官方 API 厂商状态，下方为项目与会话；窄屏上下排列。

- Provider：名称、类型、用量或余额、接口返回的模型列表。
- 官方 API：独立查询 OpenAI、Claude、xAI/Grok 的公开状态源，不依赖所选订阅工具或账号登录。
- 项目与会话：按项目组织本地会话，按原账号和实例身份快速恢复。

`Tab` / `Shift+Tab` 切换看板；`r` 手动刷新。默认每 60 秒刷新，`refresh_seconds = 0` 关闭自动刷新。网络查询在后台执行，界面可继续操作。

定时刷新和返回首页时，后台重新核对本地配置、更新余额／用量，复用连接未变化的模型查询结果，不重复请求模型列表。首次加载、新增 Provider、推理端点或推理凭据变化时查询模型；按 `r` 则强制重新查询。刷新过程中保留同一连接的现有内容，并显示更新状态，避免模型和金额反复切换到“查询中”；不同连接之间不复用旧数据。模型缓存只存在于本次 TUI 运行期间。

## Provider 与模型列表

Provider 目录读取 Usage 托管账号的当前保存版本，也包含 `[[resources]]` 中显式配置了 `inference` 的独立连接。已通过 `profile_ids` 关联到现有托管账号的资源不重复作为另一个 Provider 展示。仅配置余额查询、没有推理端点的资源不属于 Provider 目录。

当前类型：

| 类型 | 识别规则 |
| --- | --- |
| 官方 API · BYOK | HTTPS 默认端口上的 `api.openai.com`、`api.anthropic.com`、`api.x.ai` |
| 兼容 API · BYOK | 其他已配置的推理端点，包括 New API 等中转站 |
| 官方订阅 · OAuth | Usage 托管的 Codex OAuth 账号 |

接口兼容性不能证明站点使用了 New API，也不能确定其上游厂商；不根据模型名称或响应中的 `owned_by` 猜测站点实现。此目录目前不自动读取本机所有 Agent 的 API 密钥，也不把 `providers` 中的订阅查询工具名称当作已配置的 BYOK 连接。

模型通过推理端点的 `GET models` 获取：根地址补为 `/v1/models`，已包含 `/v1` 或自定义前缀时保留前缀并追加 `/models`。OpenAI、xAI 与 New API 使用 Bearer 推理密钥；官方 Anthropic 使用 `x-api-key` 与 `anthropic-version`，按 `has_more` / `last_id` / `after_id` 读取完整分页。只调用列表接口，不发起推理请求。

首页称其为“接口模型列表”：这表示当前凭据可见的模型，不保证每个模型都能用于 Codex、Responses 或其他特定 Agent。Provider 看板一次只展示当前 Provider。`←` / `→` 循环切换 Provider，`↑` / `↓` 或 `j` / `k` 仅滚动当前 Provider 的用量、余额与模型信息；标题固定显示当前名称和序号。默认预览前 3 个模型，显示剩余数量；按 `Enter` 展开／收起全部模型，`Esc` 从展开状态返回预览。切换 Provider 时回到顶部并收起模型；后台刷新按身份保留选择和滚动位置，当前 Provider 被移除时回到第一个。中文和长模型名称随宽度换行。

配置中的默认模型单独标注为“默认模型（配置）”，不作为接口可用性证明。Usage 托管的 Codex OAuth 账号参考 Magpie 的 `internal/provider/codex_models.go`，查询 `https://chatgpt.com/backend-api/codex/models?client_version=…`：使用该账号独立 Home 中的访问令牌和 `ChatGPT-Account-Id`，先核对保存的用户与工作区身份，过滤隐藏模型、去重并保留后端优先级顺序。模型随账号套餐和客户端版本变化，不维护固定的订阅模型名单，也不把 OAuth 令牌发送到 BYOK `/v1/models` 接口。此地址是 ChatGPT 的 Codex 后端协议，可能随客户端升级变化。

客户端版本取已安装 Codex CLI、同一账号 Home 的 `models_cache.json.client_version` 和兼容基线 `0.159.0` 中较新者。后台版本探测最多 2 秒，成功和失败均缓存 10 分钟；缓存文件只提供版本号，不读取其中的模型列表作为当前账号结果。每个账号独立查询，查询缓存身份包含端点、凭据、工作区和缓存版本。Usage 不在模型查询时刷新或写回 OAuth 令牌，登录失效时重新登录，或先由官方 CLI 刷新后按 `r` 重查。接口不支持、认证失败、限流、网络错误、空列表分别表达，查询失败不会保留旧模型列表冒充本次成功。

托管 BYOK 账号查询固定使用该保存版本的推理密钥；独立连接只解析 `inference.credential_env`，不使用余额或组织管理凭据。密钥不进入目录快照、界面或错误文本；模型与用量查询最多跟随 5 次同源跳转，不跨来源转发查询凭据。首页继承启动时的环境变量，其他 shell 后来执行的 `export` 不会修改它。

接口依据：[OpenAI List models](https://developers.openai.com/api/reference/resources/models/methods/list)、[New API 原生 OpenAI 格式](https://docs.newapi.ai/zh/docs/api/ai-model/models/list/listmodels)、[Anthropic List Models](https://platform.claude.com/docs/en/api/models/list)、[xAI Models](https://docs.x.ai/developers/rest-api-reference/inference/models)。

## 用量与余额

Provider 状态放在模型列表前，查询独立于模型列表，模型接口失败不影响余额显示；不依赖 Run、运行进程或会话记录。

查询来源按以下顺序决定：

1. Usage `[[resources]]` 中通过 `profile_ids` 关联到该托管账号的配置。没有启动记录也能查看；独立推理连接则展示自己的资源。共享的同一资源只查询一次，结果可显示在各关联 Provider 上。
2. 托管 Codex OAuth 账号直接读取自己的 Home 和官方订阅额度接口；不读取默认账号或系统 Keychain。此订阅来源及其重置能力独立保留，显式关联的其他资源作为额外来源展示，不替换 OAuth 账号本身。

3. 正在跟随 CC Switch、保存版本未被本地修改、推理端点与密钥仍匹配源 Provider 的账号，读取源数据库中已启用的用量配置。只读打开指定来源，停止跟随后不再读取；不导入或执行 JavaScript。

Codex 访问令牌的 JWT `exp` 到期前 5 分钟，以及缺少可用 `exp` 且超过 8 天未刷新的凭据，仅提示“令牌待刷新”；这不能证明整个 OAuth 登录失效。额度请求成功即显示有效；网络故障和 5xx 保留暂时失败状态；401 的 `token_expired` 提示由官方 Codex 刷新，只有明确的撤销或刷新凭据失效错误码才提示重新登录。遇到令牌拒绝时，Usage 重读凭据；若同一账号的令牌已被 Codex 轮换，则仅用新令牌重试一次。普通 401、403 不推断刷新凭据已失效。Usage 不为状态检查单独刷新令牌，也不写回 Codex 凭据。

支持 CC Switch 的 `newapi`、`sub2api`、`balance` 内置查询参数。旧版没有 `templateType` 的 `{{baseUrl}}/api/usage/token` 脚本也可识别。New API 账号模板使用 Access Token 与用户 ID；令牌模板使用推理 API Key。两种权限范围分别展示，令牌额度不限量不代表账号余额无限。

OAuth 订阅响应中的主动重置次数作为 `reset_credits` 资源指标进入首页，保留真实的 0；未返回时显示“次数未返回 · x 查询”。`x` 只查询当前选中的 Provider，不搜索旧用量工具列表或默认账号。查询完成后更新该资源绑定的已加载次数；确认框固定持有同一账号的重置能力，按 `y` 提交，成功后刷新额度与次数。不支持重置的 Provider 明确提示不支持。

官方订阅额度的各时间窗口复用原有 dot 圆点条，实心圆表示已用额度，旁边显示已用百分比和重置时间。颜色沿用 Agent 配色与用量阈值：70% 橙色、90% 红色，Grok 保持黑白；窄屏继续按终端宽度换行。

旧版令牌脚本如果明确以同一个正数常量除 `total_used` / `total_available`，并声明固定三位币种，可复用这项显式换算，包括旧模板中只赋值一次的 `var unit = 500000` 形式。未知表达式、单位或复杂自定义脚本不推测换算。首页不显示原始额度，底层快照和资源 CLI 保留原始值供排查。不会把 500000 或 USD 作为所有站点的默认值。

New API 的标准账号接口需要 `accessToken` 与 `userId`。令牌接口则与 CC Switch 的已配置换算保持一致：始终保留 `total_available`，即使 `unlimited_quota=true`，也按显式比例和币种显示“余额（接口返回）”，并单独显示“令牌不限额”。零余额和负余额同样保留；未配置换算时不显示原始额度或添加默认币种，有限额时提示需要配置比例和币种。金额来源仍标注为令牌接口，其是否等于账号钱包由站点定义，不要求用户为已有的令牌查询额外配置账号凭据。

余额类型的内置适配器覆盖 DeepSeek、StepFun、SiliconFlow 中／国际站、OpenRouter 和 Novita；按 CC Switch 源码中的接口接入资源注册表。严格匹配官方主机，未配置未知中转站时不遍历猜测余额接口。金额使用十进制字符串，不因缺字段生成零余额，不把零余额或欠费当作 Key 失效。Sub2API 的令牌总额度、钱包剩余值及不限量状态分别处理；无币种时保留原始额度。OpenAI 官方费用仍需单独配置 `openai_costs` 与 Admin Key。

无配置、未启用、来源身份变更、凭据缺失、认证失败、网络失败均显示原因。查询失败时清除该轮可用金额，避免把上次值当作当前余额。币种、账号／令牌／组织／项目范围、费用周期和查询时间保留；界面仍不显示 Run、会话和启动时间。余额／额度与模型列表共同按 `r` 或自动刷新更新。

接口参考本地 CC Switch 的 [用量说明](/Users/alphadoiy/Coding/cc-switch/docs/user-manual/zh/2-providers/2.5-usage-query.md)、[余额实现](/Users/alphadoiy/Coding/cc-switch/src-tauri/src/services/balance.rs) 和 [模板定义](/Users/alphadoiy/Coding/cc-switch/src/components/UsageScriptModal.tsx)。

## 官方状态与快速恢复

官方状态默认以“符号 + 厂商名称 + 状态文字”列出，不用柱高表达离散状态。正常 `●`、维护 `◆`、降级 `▲`、部分故障 `!`、严重故障 `×`、未知 `○`，配合对应颜色；正常与未知不只靠颜色区分。高度足够时附带查询时间或事件摘要。查询失败显示灰色“查询失败／更新失败”，事件详情不完整单独标记；上次报告状态单独注明，不把旧结果显示为当前正常或故障。

在厂商看板用 `↑` / `↓` 选择厂商，`Enter` 查看事件、受影响服务、最近查询时间、错误详情和官方来源地址；详情用 `↑` / `↓` 滚动，`Esc` 返回列表并保留厂商选择。刷新保留选择与详情位置，不触发会话恢复。

历史放在详情中，以等高状态符号保留本次 TUI 运行中最近 24 次查询，横向按查询顺序排列；符号形状、颜色和文字图例共同表达状态。不是按固定分钟补齐的历史，不计算健康百分比或 API 成功率。查询失败、刷新后保留旧快照、事件详情不完整时，新样本均为未知。退出后清空这段内存历史。

这里是厂商官方状态页的整体报告，不是对用户本机网络、推理端点、密钥有效性或实际请求延迟的探测。Grok 的“未报告故障”沿用 RSS 的语义。状态刷新独立于 BYOK 查询，不发送 Agent 或管理凭据。

项目与会话看板中：`↑` / `↓` 选项目，`Enter` 或 `→` 进入对应会话列表，再按 `Enter` 恢复；`←` 返回项目列表。`/` 搜索，`c` 清除，`R` 切换恢复方式。宽度足够时两个列表并排，较窄时显示当前聚焦列表。会话先显示标题，再显示账号／实例名称和活动时间；托管实例用账号名称和版本替代内部编号，没有标题时显示“未命名会话”。

快速恢复与 F3 复用同一启动链路，使用原会话的 Agent、Home、实例和项目，不根据当前 Provider 重新分配账号。自动模式在 Ghostty 中使用分屏，其他终端使用当前终端；原来的手动模式选择保持有效。后台刷新保留选择和列表焦点，刷新中禁止恢复旧列表，恢复请求在完成前不会重复提交。F3 保留完整搜索、用量排序与命令复制等功能；F4 用于管理账号和启动新运行。

项目标题只显示目录名和收录数量，例如 `usage (12)`，不显示首页未加载的 Token 累计值。会话按 Home 扫描，目录本身不证明 Run 归属；经过生命周期事件核验的会话会附带运行状态，同一会话的多个运行实例分别保留。活动状态由独立的本地只读轮询更新，不触发 Provider 或网络刷新，详见[运行生命周期](run-lifecycle.md)。项目列表由独立项目库与会话目录合并：手动添加的项目即使没有会话也会列出，标题为 `名称 (0)`，会话栏提示通过 F4 启动；置顶项目以 `★` 标记并排在前面；移出列表的目录及其会话不在首页显示，F3 会话浏览器仍完整列出。项目库读取失败时保留上次结果并显示提示。在首页选中项目后按 F4，管理页以该项目为默认启动目录。


## 数据与查询边界

首页使用 `provider_catalog::CatalogService` 只读发现 Provider，在后台分别准备模型与资源查询计划，不扫描 Run。资源复用 `ResourceRegistry` / `ResourceService` 的校验、查询、超时和失败隔离。最多并发 4 个模型列表请求，每项总查询期限为 12 秒；任务失败互不影响。每项最多 20 页、5000 个模型，分页失败或循环时不展示部分结果为完整列表。模型 ID 去重并排序，不持久化这份目录。

手动刷新取消上一轮查询，定时刷新和返回首页复用进行中的查询；返回结果按刷新代次与 Provider 身份匹配，重复、未知或过期结果不会覆盖当前目录。模型缓存按 Provider、推理端点和凭据指纹匹配，资源内容按 Provider、资源绑定和服务匹配；指纹不含明文密钥。更新失败后展示本次错误并清除失败项目的旧值，不冒充本次成功。配置加载失败会清除旧目录。退出 Dashboard 时取消查询任务。目录发现使用后台阻塞任务，终端事件循环不等待网络或本地账号扫描。

Provider 看板展示资源状态，但不展示运行、项目、会话和启动时间。运行诊断仍可通过 `usage codex runs --json` 查看；显式资源余额和费用也可通过 `usage resources`、`usage resources --run <UUID>` 查看，参见[运行资源关联](run-resource-binding.md)。没有消费者的旧 `OverviewService` 已移除；运行及资源核对继续使用上述 CLI 和底层 Manager／资源服务。

`--once`、顶层 `--json`、statusline 和订阅提醒继续使用原有用量路径；F2 历史、F3 会话和 F4 账号管理保留。项目与会话看板仍可恢复原实例，不受 Provider 模型列表查询结果影响。
