# Bark 改动消融实验（2026-10-14）

## 范围与方法

评估当前未提交的 Bark 通知改动：线程来源过滤、锁屏/熄屏门控、记录文件回退、原有通知转发、诊断日志和通知内容。实验在 `/private/tmp/usage-bark-ablation-20261014/repo` 的源码副本中进行，每个变体从同一份源码恢复后只修改一个因素；不删除或修改测试断言。

测试使用本机模拟 HTTP 服务、合成会话索引及记录文件，不读取真实 Bark 配置、不发送真实推送。使用 `cargo test --offline --quiet`，所有用例串行运行；编译耗时不作为性能比较。基线运行 14 项 Bark 相关测试。删除候选日志字段的变体及最终工作区版本运行完整回归：187 项库测试和 23 项集成测试。

## 结果

| 变体 | 实际修改 | 结果 | 判断 |
| --- | --- | --- | --- |
| 基线 | 保留当前实现 | 14 项 Bark 测试通过 | 对照组 |
| 关闭来源门控 | 将非用户线程的返回分支改为不执行，保留来源查询 | 标题/子代理过滤测试失败，服务端收到额外推送 | 必须保留 |
| 关闭屏幕门控 | 将非 Away 状态的返回分支改为不执行 | 亮屏或状态未知时的抑制测试失败，服务端收到推送 | 必须保留 |
| 删除记录文件回退 | 索引无可用结果时直接返回 Untracked | 索引未收录、但有合法记录的用户线程被错误排除 | 必须保留 |
| 关闭原通知转发 | 不执行 previous_notify 分支 | 原通知程序没有生成预期记录，兼容性测试失败 | 必须保留 |
| 删除全部候选诊断字段 | 删除 event_id、thread_key、has_turn_id 和字段内重复 PID；删除 Bark 模块中的 SHA-256 计算 | 完整 210 项测试通过 | 可以精简部分字段，但通过测试不能证明所有诊断能力等价 |
| 最终精简 | 只删除 thread_key、has_turn_id 和字段内重复 PID，保留 event_id | 工作区完整 210 项测试通过 | 已实施 |

## 已实施的精简

删除三个可以从已有日志直接获得的字段：`thread_key` 可由原始 `thread_id` 推导，`has_turn_id` 可由 `turn_id` 是否存在判断，重复的数字 `process_id` 已由 span 中的 `pid` 提供。span 的 UUID `process_id` 仍保留，用于区分 PID 被复用后的不同进程。

保留 `event_id`：旧日志只记录过事件指纹，它仍可连接历史排查证据；审批事件的指纹还包含 payload，同一个线程/轮次发生不同审批请求时有额外诊断价值。它不参与发送门控、不做去重。消融后所有测试通过，只说明受测功能保持，不能据此删除测试未覆盖的诊断用途。

实际日志中的三个新版 `bark_event_received` 事件，经统一 JSON 序列化后，从合计 3,875 字节减少到 3,522 字节，少 353 字节，约 9.1%。这是接收事件的字段体积比较，包含原有 span；不是全部日志的体积降幅，也不是通知耗时或 CPU 收益。删除四个候选字段会减少约 15.1%，但最终选择保留 event_id。

## 应保留的结构

- 跨进程日志合并：最近一次实际启动的 27 条已关联通知日志分散在三个文件；只看最新进程文件会丢失两次标题回调。按时间合并和 run_id 筛选有实际排查价值。
- 回复预览与通知预览：前者在来源/屏幕门控前记录，能看见被过滤的 `{"title":"…"}`；后者在门控后记录最终准备发送的内容，包含审批理由和账号。两个阶段服务于不同问题。
- 索引优先、记录文件回退及旧 schema 兼容：现有测试覆盖无 thread_source 列、归档记录和索引缺失；不能只针对当前 state_5.sqlite 硬编码。
- 只读和未知来源抑制：不会为不存在的索引创建新文件；无持久记录仅标为 untracked，不能只凭标题 JSON 或线程 ID 形状确定来源。
- CODEX_HOME 回退：旧启动上下文不含 home 字段，保留回退才能让升级前启动的会话使用新过滤逻辑。
- 原通知转发顺序：即使 Bark 关闭或来源被过滤，账号已有的 notify 仍应收到原始事件。

## 暂不做的优化与限制

亮屏时提前返回可以省掉来源查询，但会减少被抑制线程的来源诊断；当前优先保持排查信息。来源回退会扫描 sessions/ 和 archived_sessions/，大目录中的成本仍未实测，暂不增加索引缓存、通知合并或重试机制。

来源、屏幕、回退和转发变体仅运行各自关联的失败测试；日志字段变体运行完整回归。实验不证明所有平台行为，不测 Apple Watch 投递、真实网络延迟或大规模会话目录性能。测试通过也不代表通知所说的“本轮完成”就等于整个需求完成。
